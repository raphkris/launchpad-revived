# Launchpad Revived — Requirements

**Version** `260730.01`
**Supersedes** `260730.00`
**Target** macOS 26 Tahoe

---

## 0. How to read this document

Every requirement has a stable ID (`AREA-NN`). IDs never get reused or renumbered — if a requirement dies, it is marked `[B]` or struck, not deleted. Commit messages and review reports cite these IDs.

| Marker | Meaning |
|---|---|
| **`[D]`** | **Decided.** Implement exactly as written. |
| **`[O]`** | **Open.** Do *not* implement. Needs a decision first. |
| **`[B]`** | **Backlog.** Deliberately excluded from MVP. Do not implement. |

> **Instruction to any coding agent reading this file:** implement only `[D]` items, and only those inside the currently active slice (§12). If a `[D]` requirement is ambiguous in a way that blocks you, stop and say so — do not guess. Never implement `[O]` or `[B]`.

**Changelog from `260730.00`**

- Architecture decided (§1) — was entirely unstated.
- Menu bar / Dock conflict resolved by hiding both (`WIN-03`). Consequence: `INT-09` (drag to Dock) moved to backlog, since you cannot drop onto a Dock that isn't rendered.
- Badges moved to backlog (`B-01`) — no public API exists.
- Dock reveal moved to backlog (`B-02`) — same reason.
- App discovery roots corrected to include `/System/Applications` and `~/Applications`; recursion rules specified.
- Jiggle Mode latching model defined (§6.3), replacing the struck-through timing bullets.
- JSON schema restructured: array-ordered, bundle-ID-keyed. The original object-keyed-by-name design could not round-trip.

**Corrections within `260730.01`** — applied in place rather than as a new iteration, since no code had been written against the erroneous text.

- `PRJ-10`: logger subsystem is now the literal bundle identifier, `lol.omg.rkm.LaunchpadRevived`, rather than a placeholder.
- §12, Slice 1: discovery scope narrowed to `DISC-01`–`DISC-10` and `DISC-12`. `DISC-11` had been included by an ID range that swept it up, but it depends on folders and belongs to Slice 3, where it was already listed.

## 1. Project constraints

| ID | | Requirement |
|---|---|---|
| `PRJ-01` | `[D]` | Swift 6. Strict concurrency checking enabled. |
| `PRJ-02` | `[D]` | **AppKit application shell, SwiftUI view content.** `NSApplicationDelegate` + a custom borderless `NSWindow`; content is a SwiftUI hierarchy hosted in `NSHostingView`. Rationale: window level, collection behavior and `presentationOptions` have no SwiftUI equivalent, while the Liquid Glass APIs are SwiftUI-first. |
| `PRJ-03` | `[D]` | Formatting via `swift-format` (Apple-maintained, ships in the toolchain). A `.swift-format` config is committed at repo root. No other formatter. |
| `PRJ-04` | `[D]` | Naming and API shape follow the Swift API Design Guidelines. |
| `PRJ-05` | `[D]` | Liquid Glass surfaces use the system SwiftUI glass APIs (`glassEffect`, `GlassEffectContainer`, glass button styles). Hand-rolled blur/vibrancy imitations are not acceptable. |
| `PRJ-06` | `[D]` | **No third-party dependencies.** System frameworks only. Adding a package requires explicit approval. |
| `PRJ-07` | `[D]` | Deployment target macOS 26.0. |
| `PRJ-08` | `[D]` | App is **unsandboxed**. It reads `/Applications`, launches arbitrary apps, and moves bundles to Trash — none of which survive the App Sandbox. This forecloses Mac App Store distribution; acceptable and intentional. |
| `PRJ-09` | `[D]` | One primary type per file. Target ≤ 300 lines per file. Rationale: every change is reviewed against this spec by reading a diff — large files make that unreliable. |
| `PRJ-10` | `[D]` | No `print()` for diagnostics. Use `os.Logger` with subsystem `lol.omg.rkm.LaunchpadRevived`, matching the app's bundle identifier. The sole exception is a diagnostic mode whose entire purpose is writing to stdout. |

## 2. Environment & build

| ID | | Requirement |
|---|---|---|
| `ENV-01` | `[D]` | Development, build and UAT all happen on the Tahoe machine. Xcode 26.4+ (earlier Xcode cannot run on Tahoe 26.2+; later Xcode cannot run on Sequoia — the toolchain is pinned to the target machine). Version pinned in `.xcode-version`. |
| `ENV-02` | `[D]` | `./run.sh` at repo root builds, relaunches, and writes a full build log to `.build/last-build.log`. This is the only sanctioned build command. `--build` builds without launching. |
| `ENV-03` | `[D]` | A coding agent must run `./run.sh --build` after any code change and must resolve build failures before reporting completion. **Agents never launch the app** — see `WIN-03` and `WIN-12` for why. |
| `ENV-04` | `[B]` | Packaging, code signing, notarization, `.dmg` creation. The app runs from `.build/` and is never installed. |

## 3. App discovery

| ID | | Requirement |
|---|---|---|
| `DISC-01` | `[D]` | Scan roots: `/Applications`, `/System/Applications`, `~/Applications`. |
| `DISC-02` | `[D]` | Recurse into subdirectories using `FileManager` with `.skipsPackageDescendants` and `.skipsHiddenFiles`. The package-descendant flag is what stops the scanner walking into `Xcode.app` and indexing its embedded apps. |
| `DISC-03` | `[D]` | Depth cap of 3 below each root, as a safety net independent of `DISC-02`. |
| `DISC-04` | `[D]` | Only `.app` bundles are candidates. Not `.appex`, `.prefPane`, `.service`. |
| `DISC-05` | `[D]` | Exclude bundles whose `Info.plist` declares `LSUIElement == true` or `LSBackgroundOnly == true`. These are background agents with no UI. |
| `DISC-06` | `[D]` | Subdirectories are **flattened** — a directory never becomes a Launchpad folder. Apps inside `/Applications/Foo/` appear individually at top level. |
| `DISC-07` | `[D]` | Identity is `Bundle(url:)?.bundleIdentifier`. When `nil` (rare, malformed bundles), fall back to a stable hash of the absolute path. Identity is never the display name. |
| `DISC-08` | `[D]` | Display name is the Finder-localized name: `url.resourceValues(forKeys: [.localizedNameKey])`. Not `CFBundleName`. |
| `DISC-09` | `[D]` | Icon via `NSWorkspace.shared.icon(forFile:)`. |
| `DISC-10` | `[D]` | App Store provenance = existence of `Contents/_MASReceipt/receipt` inside the bundle. Gates `DEL-01`. |
| `DISC-11` | `[D]` | **First-run seeding only:** contents of `/System/Applications/Utilities` are placed into an auto-created folder named `Other`. This happens once, when no layout file exists. Thereafter `Other` is an ordinary user-editable folder with no special status — it can be renamed, emptied, or destroyed like any other. **Slice 3** — depends on folders existing. |
| `DISC-12` | `[D]` | Rescan on every Launchpad open. |
| `DISC-13` | `[B]` | Live refresh via FSEvents while Launchpad is open. |

## 4. Window & presentation

| ID | | Requirement |
|---|---|---|
| `WIN-01` | `[D]` | A single borderless `NSWindow` sized to the full frame of the **main display** — the one bearing the menu bar, i.e. `NSScreen.screens.first`. Mouse position has no influence. |
| `WIN-02` | `[D]` | Window level `.screenSaver`, above all ordinary content. |
| `WIN-03` | `[D]` | While open: `NSApp.presentationOptions = [.hideDock, .hideMenuBar]`. Restore the prior value on close. (These two must be set together — `.hideMenuBar` is invalid without `.hideDock`.) |
| `WIN-04` | `[D]` | `collectionBehavior = [.canJoinAllSpaces, .stationary, .fullScreenNone]`. |
| `WIN-05` | `[D]` | Non-main displays are left untouched — not covered, not dimmed. |
| `WIN-06` | `[D]` | Background is the main display's wallpaper via `NSWorkspace.shared.desktopImageURL(for:)`, drawn aspect-fill and blurred. Captured at open, not live. |
| `WIN-07` | `[O]` | Behavior when the wallpaper is dynamic, video, or otherwise not a single static image. Needs investigation on the target machine. |
| `WIN-08` | `[D]` | Invocation: activating the app (clicking its Dock or Finder icon). This is the only MVP trigger. |
| `WIN-09` | `[D]` | The app has a normal Dock presence (`LSUIElement` unset). Note this interacts with `WIN-03` — its own icon disappears along with the Dock while Launchpad is open, which is correct. |
| `WIN-10` | `[D]` | `applicationShouldHandleReopen` re-presents the window when the app is already running. |
| `WIN-11` | `[D]` | Dismissal on: `⎋`; click on empty background; launching an app (`INT-01`); the window resigning key. |
| `WIN-12` | `[D]` | `presentationOptions` must be restored on dismissal *and* on abnormal termination paths. A crash that leaves the user with no menu bar and no Dock is the worst failure mode this app has. |

## 6. Interaction

### 6.1 Launching

| ID | | Requirement |
|---|---|---|
| `INT-01` | `[D]` | Single click on an app icon launches it via `NSWorkspace.openApplication` and dismisses Launchpad. |
| `INT-02` | `[D]` | If the app is already running, activate the existing instance rather than spawning a second. |

### 6.2 Dragging

| ID | | Requirement |
|---|---|---|
| `INT-03` | `[D]` | Icons can be dragged to reorder within a page. Remaining icons reflow to close the gap. |
| `INT-04` | `[D]` | Dragging to the left/right edge of the page turns the page after a dwell of `pageTurnDwellDuration` (see `JSN-09`). |
| `INT-05` | `[D]` | Dropping an app onto another app creates a folder (`FLD-01`). |
| `INT-06` | `[D]` | Dropping an app onto a folder adds it to that folder. |
| `INT-07` | `[D]` | Folders cannot be dropped onto apps or other folders (`FLD-05`). |
| `INT-08` | `[D]` | A drag that ends on empty space returns the icon to its origin. |
| `INT-09` | `[B]` | Dragging an app icon out to the Dock. Blocked by `WIN-03` — there is no Dock on screen to drop onto. Returns with `B-02`. |

### 6.3 Jiggle Mode

Two entry paths, one latch flag.

| ID | | Requirement |
|---|---|---|
| `JIG-01` | `[D]` | `⌥` key down enables Jiggle Mode. `⌥` key up disables it **unless latched**. |
| `JIG-02` | `[D]` | Press-and-hold on an icon for `jiggleLatchHoldDuration` (see `JSN-09`) enables Jiggle Mode **latched**, and begins a drag session in the same continuous gesture. The hold and the drag are not separate actions. |
| `JIG-03` | `[D]` | Clicking a delete affordance (`DEL-01`) while `⌥` is held sets the latch, so Jiggle Mode survives the subsequent key-up. |
| `JIG-04` | `[D]` | Latched Jiggle Mode ends on: `⎋`; click on empty background; app launch; Launchpad dismissal. |
| `JIG-05` | `[D]` | Jiggle animation applies to all icons and folders simultaneously, not just the one under the cursor. |

### 6.4 Deletion

| ID | | Requirement |
|---|---|---|
| `DEL-01` | `[D]` | In Jiggle Mode, an `x.circle` affordance appears in the corner of eligible icons only. Eligible = App Store apps (`DISC-10`) and Safari web apps. Everything else shows no affordance. |
| `DEL-02` | `[O]` | How to positively identify a Safari web app. Needs investigation — likely a marker in the bundle under `~/Applications`. |
| `DEL-03` | `[D]` | Clicking the affordance presents a confirmation alert with `Cancel` and `Remove` buttons. |
| `DEL-04` | `[O]` | Exact alert copy. Draft: *Are you sure you want to remove the app "{name}"?* — needs the real strings, including the noun used for web apps. |
| `DEL-05` | `[D]` | `Remove` is the prominent (default, tinted) button. |
| `DEL-06` | `[D]` | When Full Keyboard Access is enabled in System Settings, initial focus lands on `Cancel`. |
| `DEL-07` | `[D]` | Removal moves the bundle to Trash via `NSWorkspace.shared.recycle` — never an unrecoverable delete. |
| `DEL-08` | `[D]` | On successful removal the icon is removed from the layout and the layout file is rewritten. On failure, the alert reports the error and the layout is unchanged. |

## 9. Persistence

### 9.1 File

| ID | | Requirement |
|---|---|---|
| `JSN-01` | `[D]` | Location: `~/Library/Application Support/LaunchpadRevived/layout.json`. |
| `JSN-02` | `[D]` | Written debounced (250 ms) after any mutation, and unconditionally on dismissal. |
| `JSN-03` | `[D]` | Written atomically. A partial write must never leave an unparseable file. |
| `JSN-04` | `[D]` | Human-editable and diff-friendly: pretty-printed, keys in a stable order. |
| `JSN-05` | `[B]` | Hot-reloading external edits while running. For now, edits are picked up on next launch. |

### 9.2 Schema

| ID | | Requirement |
|---|---|---|
| `JSN-06` | `[D]` | `layout` is an **array**. Position is array index; page is `index / 35`. Order is never inferred from object key order. |
| `JSN-07` | `[D]` | Apps are identified by `bundleID` (`DISC-07`). `name` and `path` are written as advisory, human-readable hints only and are never used for lookup. |
| `JSN-08` | `[D]` | `schemaVersion` is present and checked on load. An unrecognized version is a hard failure with a clear message, not a silent reset. |
| `JSN-09` | `[D]` | Tunables live under `config` so they can be changed without a rebuild. |
| `JSN-10` | `[D]` | Reconciliation on load: an entry whose app is missing from disk is dropped; an app on disk with no entry is appended after the last existing entry. Folder membership is preserved across both. |

```json
{
  "schemaVersion": 1,
  "state": {
    "page": 0,
    "openFolderID": null
  },
  "config": {
    "jiggleLatchHoldDuration": 0.5,
    "pageTurnDwellDuration": 0.75
  },
  "layout": [
    {
      "type": "app",
      "bundleID": "com.apple.Safari",
      "name": "Safari",
      "path": "/Applications/Safari.app"
    },
    {
      "type": "folder",
      "id": "F-8A31C2",
      "name": "Other",
      "items": [
        {
          "type": "app",
          "bundleID": "com.apple.ActivityMonitor",
          "name": "Activity Monitor",
          "path": "/System/Applications/Utilities/Activity Monitor.app"
        }
      ]
    }
  ]
}
```

## 10. Backlog

Deliberately out of MVP. Do not implement.

| ID | Item | Why |
|---|---|---|
| `B-01` | Notification badges on icons, honoring per-app Badges settings | No public API exists to read another app's badge count. All known routes are private frameworks, an undocumented database requiring Full Disk Access, or scraping the Dock via Accessibility. Needs a timeboxed spike before it can be specified. |
| `B-02` | Dock visible while Launchpad is open, including revealing an auto-hidden Dock | No public API to force the reveal. Also architecturally awkward: Apple's Launchpad can do this because it *is* the Dock process. |
| `B-03` | Dragging app icons out to the Dock (`INT-09`) | Depends on `B-02`. |
| `B-04` | Trackpad gesture trigger | Explicitly out per `260730.00`. |
| `B-05` | Hot Corners trigger | Explicitly out per `260730.00`. |
| `B-06` | Keyboard shortcut trigger | Achievable externally via Karabiner Elements meanwhile. |
| `B-07` | Live app-list refresh (`DISC-13`) | |
| `B-08` | Multi-display support beyond `WIN-05` | |
| `B-09` | JSON hot reload (`JSN-05`) | |
| `B-10` | Optional badge value on the icon view | **Not backlog — see note.** The icon view should accept an optional badge value from day one and always receive `nil`. It is a single optional parameter now versus reworking the icon layout later. |

## 12. Slices

### Slice 1 — Shell, discovery, static grid ← *active*

Purpose: de-risk the two things most likely to go wrong, before anything is built on top of them.

**In:** `PRJ-01`–`PRJ-10`, `ENV-02`, `ENV-03`, `DISC-01`–`DISC-10`, `DISC-12`, `WIN-01`–`WIN-06`, `WIN-08`–`WIN-12`, `LAY-01`, `LAY-02`, `LAY-04`, `LAY-05`, `LAY-07`, `INT-01`, `INT-02`, `B-10`.

**Explicitly out:** all dragging, all folders, all jiggle, all deletion, all search, all persistence. `DISC-11` is **not** in this slice — it needs folders and belongs to Slice 3. Discovery order in Slice 1 is alphabetical and not persisted.

**Done when:** the app launches, covers the main display with a blurred wallpaper, hides the menu bar and Dock, shows every discovered app in a paginated 5×7 grid with correct names and icons, launches an app on click, dismisses correctly, and restores `presentationOptions` every time.

### Slice 2 — Persistence & reordering
`JSN-01`–`JSN-13`, `INT-03`, `INT-04`, `INT-08`. Layout survives relaunch and is hand-editable.

### Slice 3 — Folders
`FLD-01`–`FLD-15`, `INT-05`–`INT-07`, `DISC-11`. Requires `FLD-02`, `FLD-08`, `FLD-09` answered first.

### Slice 4 — Jiggle & deletion
`JIG-01`–`JIG-05`, `DEL-01`–`DEL-08`. Requires `DEL-02`, `DEL-04` answered first.

### Slice 5 — Search
`SRC-01`–`SRC-09`. Requires `SRC-05`, `SRC-06`, `SRC-09` answered first.
