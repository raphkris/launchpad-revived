## 1. Decision record

**D1 — app switcher vs. Dock icon.** Hiding the app from `⌘⇥` was requested and is **rejected for MVP**. `LSUIElement = true` removes the Dock icon and the app-switcher entry together; there is no public API that separates them. `WIN-08` makes clicking the Dock icon the only MVP invocation path, so hiding from the switcher would leave the app with no way to open. Filed as `B-11`.

The consequence is accepted: LaunchpadRevived appears in `⌘⇥` while running. `WIN-14` limits the damage by dismissing the moment focus leaves.

## 3. New requirements

| ID | | Requirement |
|---|---|---|
| `WIN-13` | `[D]` | **Focus returns to the previously active application on dismissal.** Ordering the window out is not sufficient — the app remains frontmost with an empty menu bar. Use `NSApp.hide(nil)`, which deactivates and hands focus to the next application in order. `NSApplication.deactivate()` is not a substitute; it is unreliable for borderless windows at `.screenSaver` level. **Exception:** the launch dismissal path (`INT-01`) must *not* hide — the launched application takes focus itself, and hiding races it. |
| `WIN-14` | `[D]` | **Dismiss when the application resigns active.** Implement via `applicationDidResignActive` on the app delegate. This covers `⌘⇥`, Mission Control, Spotlight, and any other activation of a different application. Dismissal must remain idempotent — `WIN-11`, `WIN-14` and the existing resign-key path can all fire for one user action, and the second and third must be no-ops. |
| `WIN-15` | `[D]` | **Present and dismiss fade the window's opacity.** Animate `window.animator().alphaValue` inside an `NSAnimationContext` group. Present: set `alphaValue = 0`, order front, animate to `1`. Dismiss: animate to `0`, then in the completion handler order out, restore `presentationOptions`, and apply `WIN-13`. Restoring presentation options *before* the fade completes is wrong — the Dock and menu bar reappear while Launchpad is still on screen. SwiftUI's `.contentTransition` is **not** the mechanism here; it animates content changes within a view, not window presentation. |
| `WIN-16` | `[D]` | **Fade durations are named constants in one place:** `windowFadeInDuration = 0.15`, `windowFadeOutDuration = 0.12` (seconds). These move under `config` (`JSN-09`) in Slice 2; do not build a persistence path for them now. |
| `WIN-17` | `[D]` | **Termination skips the fade.** On `applicationWillTerminate` / `applicationShouldTerminate`, restore `presentationOptions` synchronously and immediately. `WIN-12` outranks `WIN-15` — an animation must never sit between a terminating process and a restored menu bar. |

## 4. File ownership

Ownership is exclusive and binding.

**Owned by this delta — edit freely:**

- `LaunchpadRevived/AppDelegate.swift`
- `LaunchpadRevived/LaunchpadSessionController.swift`
- `LaunchpadRevived/LaunchpadWindow.swift`
- `LaunchpadRevived/WindowResignDelegate.swift`
- `LaunchpadRevived/PresentationOptionsGuard.swift`
- `LaunchpadRevived/Info.plist`

**Out of scope — do not edit, and do not change behavior that lives in them:**

- `AppGridView.swift`, `PageIndicatorView.swift`, `AppIconView.swift`, `GridLayout.swift`, `LaunchpadRootView.swift`, `LaunchpadViewModel.swift`

If satisfying a requirement in this delta appears to require touching one of those files, stop and say so rather than editing it.

**Known seam.** `LaunchpadSessionController.installKeyMonitor` currently handles key codes `123` and `124` (left/right arrow) for page turns. This delta **removes those two cases**, leaving Escape only — bare arrow keys are being reassigned to focus navigation in a separate work stream that handles them in the SwiftUI layer. Arrow-key page navigation will therefore be absent once this delta lands. That is expected and correct; do not reinstate it, and do not implement a replacement.

## 5. Done when

- Dismissing by `⎋` or by clicking the background returns focus to the application that was frontmost before Launchpad opened; the menu bar shows that app, not LaunchpadRevived.
- Pressing `⌘⇥` while Launchpad is open dismisses it immediately.
- Clicking an app icon launches it, Launchpad disappears, and the launched app — not the previously frontmost one — ends up with focus.
- Open and close fade rather than snapping.
- The Dock and menu bar are restored on every path, including force-quit and `⌃C` from the build script, and never reappear before the fade-out finishes.
- `./run.sh --build` succeeds and `swift-format` has been run.
