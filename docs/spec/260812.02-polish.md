# Launchpad Revived — Delta: Transition, Hover, Scroll, Render Performance

**Version** `260812.02`
**Amends** `260730.01`, `260812.00`, `260812.01`
**Slice** 1.2 — UAT corrections from the Slice 1.1 pass
**Target** macOS 26 Tahoe

## 0. How to read this document

Marker semantics are unchanged: `[D]` decided, implement as written. `[O]` open,
do not implement. `[B]` backlog, do not implement. Earlier documents remain
canonical for anything not named here; where they conflict, this document wins.

**Origin.** UAT on the Tahoe machine, 2026-08-12, against the merged Slice 1.1 build.

## 1. Explicitly out of scope

Do not touch `WIN-03`, `WIN-12`, `WIN-17`, `PresentationOptionsGuard`, or the
window level. UAT found the Dock and menu bar hiding abruptly, and a change is
coming — but it depends on a product pivot that has not been specified yet.
Leave that machinery exactly as it is. A consequence: the fade in `WIN-15` will
still be preceded by an instant Dock and menu bar pop after this delta. That is
expected and is not a bug to fix here.

Folders (Slice 3) and Jiggle Mode (Slice 4) remain unimplemented and out of scope.

## 2. Amendments

| ID | | Amendment |
|---|---|---|
| `WIN-16` | `[D]` | Fade durations become `windowFadeInDuration = 0.25` and `windowFadeOutDuration = 0.18`. The previous 0.15 / 0.12 were too short to read as a transition. |
| `LAY-06` | `[D]` | Rewritten. See `LAY-14` for the transition model. Additionally, for non-precise scroll events (a mouse wheel), use whichever of `scrollingDeltaX` or `scrollingDeltaY` has the larger magnitude as the page axis. A standard wheel emits vertical deltas only, so the current X-only reading makes the feature inert on wheel hardware. Precise events (trackpad) remain horizontal-only. |
| `LAY-12` | `[D]` | Amended. There is **no hover affordance at all**. Remove the `scaleEffect` and the `onHover` handler from `AppIconView` entirely. The focus ring is the only cell state indicator. Hover must produce no visual change of any kind. |

## 3. New requirements

| ID | | Requirement |
|---|---|---|
| `LAY-14` | `[D]` | **One page-transition model, shared by trackpad scroll (`LAY-06`), background drag (`LAY-09`), keyboard (`LAY-05`) and dot taps.** Rules: (a) During a continuous gesture the page tracks input 1:1 via `pageDragOffset`, rubber-banded at the ends — the trackpad path currently does not feed `pageDragOffset` at all and must. (b) A single gesture moves **at most one page**, regardless of velocity or distance. (c) Release velocity affects only how *fast* the settle animation runs, never *which* page is landed on nor how many are crossed. Map velocity to spring response within a clamped range, roughly 0.18s for a hard flick to 0.42s for a slow release. (d) Reference behavior is the photo-to-photo swipe in Apple's Photos app. |
| `LAY-15` | `[D]` | **Nothing renders before layout metrics resolve.** `AppGridView.gridSize` starts at `.zero`, so the first frames compute `GridLayout.metrics(for: .zero)` and produce a negative `cellWidth`. Render nothing (or a plain transparent placeholder) until `gridSize` is non-zero, so the `WIN-15` fade plays over correct content instead of a malformed grid that snaps at the end. |
| `LAY-16` | `[D]` | **Render only `currentPage - 1` through `currentPage + 1`.** `pageStrip` currently iterates `0..<pageCount` inside an `HStack`, which forces every page to materialize — `LazyVGrid` gives no laziness in this arrangement. Offset arithmetic must be adjusted so the visible window still lands on the correct page. This is the primary cause of the low frame rate during page transitions. |
| `LAY-17` | `[D]` | **App icons are downsampled once and cached, not scaled per frame.** Icons currently come from `NSWorkspace` at full resolution and are handed to SwiftUI at cell size. Resize once to the largest size the grid renders at, cache keyed by bundle identifier, and serve the cached image to cells. Inspect the existing icon path before changing it and keep the public shape of `DiscoveredApp` intact. |

## 4. Environment

| ID | | Requirement |
|---|---|---|
| `ENV-05` | `[D]` | **`run.sh` builds with ad-hoc signing and reports non-compiler failures.** Signing with a developer identity requires the login keychain, which is unavailable to agents and to SSH sessions, producing `errSecInternalComponent` with no diagnostic output. `ENV-04` already backlogs signing and notarization and the app only ever runs from `.build/`, so ad-hoc signing is correct for the whole MVP. Both the build-only and the build-and-run paths use the same flags so the binary under UAT is the binary that was built. On failure, the script must also print the tail of the log, not only lines matching `error:` or `warning:`. |

## 5. Done when

- Open and close read as a fade rather than a snap, over correct grid content with no malformed first frame.
- Hovering an icon produces no visual change whatsoever.
- One trackpad flick moves exactly one page, however hard it is thrown.
- The page tracks the fingers during a trackpad swipe, as it already does during a cursor drag.
- A fast flick settles faster than a slow one, but lands on the same page.
- Page transitions and drags are visually smooth.
- `./run.sh --build` succeeds without keychain access, and a non-compiler failure prints something useful.
